Window functions in plain words

A window function computes something across a group of rows (a total, a rank, the previous value) and writes the answer onto every row. GROUP BY folds each group into one row; a window function keeps every row and adds a column.

PARTITION BY says which rows belong together (the window restarts for each group). ORDER BY inside OVER says in what order to walk them, which is what makes a running total or a "previous row" possible.

The syntax

function_name(column) OVER (
  PARTITION BY group_column  -- optional: restart for each group
  ORDER BY sort_column       -- optional: the order inside the group
)

A worked example

Weekly running distances for two runners. The table runs:

runnerweekkm
Ana15
Ana28
Ana36
Ben110
Ben27

For each runner, the distance so far and the change from the week before.

SELECT runner, week, km,
       SUM(km) OVER (PARTITION BY runner ORDER BY week) AS km_so_far,
       km - LAG(km) OVER (PARTITION BY runner ORDER BY week) AS change
FROM runs
ORDER BY runner, week;

Result:

runnerweekkmkm_so_farchange
Ana155NULL
Ana28133
Ana3619-2
Ben11010NULL
Ben2717-3

Every input row is still there. km_so_far restarts at Ben because of PARTITION BY runner, and change is NULL on each runner's first week: LAG has no earlier row to look at.

A common mistake: filtering on a window function in WHERE

WHERE ROW_NUMBER() OVER (…) = 1 fails with "misuse of window function": WHERE runs before any window is computed. Compute the window in a CTE (or a subquery) and filter on it in the outer query.

WITH ranked AS (
  SELECT runner, week, km,
         ROW_NUMBER() OVER (PARTITION BY runner ORDER BY km DESC) AS rn
  FROM runs
)
SELECT runner, week, km
FROM ranked
WHERE rn = 1
ORDER BY runner;

What are SQL window functions?

A window function performs a calculation across a set of rows related to the current row — without collapsing them the way GROUP BY does. The window is defined by an OVER clause.

Example — rank employees by salary within each department
SELECT
    employee_id,
    department,
    salary,
    RANK() OVER (
        PARTITION BY department
        ORDER BY salary DESC
    ) AS salary_rank
FROM employees;

💡 This returns every row alongside each employee's salary rank within their department — something you cannot do with GROUP BY alone.

Why window functions matter for interviews

Window functions are where hard SQL interview questions live: ranking within groups, running totals, comparisons with the previous row. They take longer to learn than joins or aggregates, so they are worth starting early.

They're also highly practical — window functions power retention cohorts, rankings, running totals, and period-over-period comparisons that data teams run every day.
