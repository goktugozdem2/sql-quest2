CTEs in plain words

A CTE (common table expression) gives a query a name for the length of one statement. You write WITH name AS (…) once, and the rest of the statement reads name as if it were a table.

Two things make it worth it: a long query reads top to bottom in steps, and a result you need twice (a total and the average of that total) is computed once and used by name.

The syntax

WITH first_step AS (
  SELECT ...
), second_step AS (
  SELECT ... FROM first_step   -- a later CTE may read an earlier one
)
SELECT ... FROM second_step;

A worked example

Support tickets and the minutes each one took. The table tickets:

agentminutes
Ana30
Ana50
Ben20
Ben25
Ben15
Caro90

The agents whose total minutes are above the average agent's total.

WITH per_agent AS (
  SELECT agent, COUNT(*) AS tickets, SUM(minutes) AS minutes
  FROM tickets
  GROUP BY agent
)
SELECT agent, tickets, minutes
FROM per_agent
WHERE minutes > (SELECT AVG(minutes) FROM per_agent)
ORDER BY minutes DESC;

Result:

agentticketsminutes
Caro190
Ana280

per_agent is used twice: once as the rows to return and once inside the subquery that averages it (80, 60 and 90 average to about 76.7). Without the CTE the GROUP BY would have to be written out in both places.

A common mistake: joining two detail tables, then summing

Join orders and refunds to the same customer and every order repeats once per refund, so SUM and COUNT come back multiplied, with no error. Aggregate each table in its own CTE first, then join the totals, one row per key on each side.
