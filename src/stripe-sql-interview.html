Debug this query

The same report asks for a chargeback rate over a date window. The window is where a correct-looking query goes wrong.

The ask: what share of April 2026's card transactions were later disputed? The query below runs on our synthetic card ledger and answers 3.51. Find the line.

1SELECT ROUND(100.0 * COUNT(c.chargeback_id) / COUNT(t.txn_id), 2) AS disputed_pct
2FROM transactions t
3LEFT JOIN chargebacks c ON c.txn_id = t.txn_id
4WHERE t.txn_at BETWEEN '2026-04-01' AND '2026-04-30';
Show the bug

Line 4: BETWEEN with a bare end date. txn_at holds a full timestamp, so '2026-04-30' means midnight at the start of 30 April, and the 35 transactions made later that day drop out, one of them disputed. April has 1,119 transactions and 39 of them were disputed, so the answer is 3.49, not 3.51. Close the window with a half-open range:

1SELECT ROUND(100.0 * COUNT(c.chargeback_id) / COUNT(t.txn_id), 2) AS disputed_pct
2FROM transactions t
3LEFT JOIN chargebacks c ON c.txn_id = t.txn_id
4WHERE t.txn_at >= '2026-04-01' AND t.txn_at < '2026-05-01';
