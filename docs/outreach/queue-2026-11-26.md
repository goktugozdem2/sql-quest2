the right customers, across a year boundary; it is not one of the mock's
questions):

```
Not a Capital One employee, so this is only what candidates describe and what
I'd drill: SQL on card-transaction tables, under a clock, where the hard part
is the grain (customer vs month vs transaction), not the syntax.

One shape worth being fast at: "customers who transacted in three consecutive
months". Collapse to one row per customer-month first, then self-join:

WITH m AS (
  SELECT DISTINCT customer_id,
         strftime('%Y-%m', txn_date) AS ym          -- Postgres: date_trunc('month', txn_date)
  FROM transactions
)
SELECT DISTINCT a.customer_id
FROM m a
JOIN m b ON b.customer_id = a.customer_id
        AND b.ym = strftime('%Y-%m', date(a.ym || '-01', '+1 month'))
JOIN m c ON c.customer_id = a.customer_id
        AND c.ym = strftime('%Y-%m', date(a.ym || '-01', '+2 month'));

The DISTINCT in the CTE is the point. Skip it and a customer with 40
transactions a month makes the join explode, and any SUM you add later is
wrong. Doing it with month arithmetic, not "month number + 1", also keeps
December → January correct.

Disclosure: I build SQL Quest, a SQL practice site. If you want more of this
on card data, I put a Capital One-style set together here:
https://sqlquest.app/capital-one-sql-interview/

Göktuğ
```
