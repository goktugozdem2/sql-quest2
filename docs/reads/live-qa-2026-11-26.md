## 4. Host redirect (#352): **FAIL**

`curl -sI https://sql-quest2.vercel.app/sql-exercises/` returns **`HTTP/2 200`**:
the page itself, no redirect. Probed paths on `sql-quest2.vercel.app`:

| path | answer |
|---|---|
| `/`, `/?x=1`, `/app/`, `/blog/`, `/sql-exercises/` | **200**, served on the vercel.app host |
| `/sql-exercises` | 308 → `/sql-exercises/` on the **same** host, then 200 |
| `/index.html`, `/app` | 308 to the same host (cleanUrls / trailing slash) |
| `/app.js`, `/robots.txt`, `/sitemap.xml` | **308 → https://sqlquest.app/<path>** (the new rule fires) |
| `/coach/` | 308 → `/app` (the path rule, not the host rule, so the host rule did not match) |

- **What the evidence shows.** The `has: host` rule is deployed: it fires
  for file paths. It never fires for a directory or HTML path, which is
  every page a crawler would index.
- **The status is 308, not 301.** That is what `"permanent": true` gives on
  Vercel. Search engines treat 308 like 301, but the brief and the PR say
  301.
- **What softens it.** Each page served on the vercel.app host still
  carries `<link rel="canonical" href="https://sqlquest.app/…">`, so the
  SEO cost is limited to duplicate crawling.
- **Not established:** why the rule skips HTML paths. Likely candidates
  are the `cleanUrls` + `trailingSlash: true` handling, which runs before
  user redirects for directory paths, or the `/:path*` source not matching
  a trailing-slash path under `trailingSlash: true`.
- **To try next, in a preview:** add `"source": "/"` and
  `"source": "/:path*/"` host-scoped entries ahead of the existing one,
  then `curl -sI` all five page paths above. Not fixed in this run.
