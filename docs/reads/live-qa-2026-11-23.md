## 1. Why the laptop smoke ran 21/31 while CI ran 31/31 — verdict (a), environment only

**Cause: the battery attached to a different Chrome than the one it started.**
`scripts/smoke-test.js` started Chrome with a fixed
`--remote-debugging-port=9222` and then read `http://127.0.0.1:9222/json`.
On the laptop, a headless Chrome from an earlier smoke run (PID 60653, started
2026-11-22 16:00, profile `/tmp/chrome-smoke-1795352419496`) was still alive
and held `127.0.0.1:9222`. The new Chrome could only bind `[::1]:9222`, so the
battery talked to the orphan instead:

```
$ lsof -nP -iTCP:9222 -sTCP:LISTEN
Google  14589  … TCP [::1]:9222 (LISTEN)        ← this run's Chrome
Google  60653  … TCP 127.0.0.1:9222 (LISTEN)    ← yesterday's orphan, page at https://sqlquest.app/app/
```

The orphan's storage still held the battery's last step (a guest at three
solves, header "Try Pro"). The first step does not clear storage, so the app
opened as a returning guest, not a first-run visitor: no "Find your SQL
starting point", `legacyNavCount: 1`, and the nine first-run, placement and
foundations checks after it failed in a chain. The failure detail shows it:
`"textSample":"💬SQL Quest🥉 Bronze0||0Log inTry P…"`.

A run that is killed from outside (a tool timeout, Ctrl-C) never reaches the
`finally` that kills Chrome, which is how the orphan was left behind. The
commit for #149 already recorded "Hermetic smoke 20/31, the same 11 failing"
on this laptop.

**Ruled out:**
- geo: the hermetic preamble answers `/api/` with `[]` in both places;
- language: the headless browser reports `en-US` (the system's en-TR is not
  passed through), and `getCurrentLang` only switches for `tr*`;
- timezone: a fresh-profile probe with `Europe/Istanbul` renders the
  first-run quiz normally;
- the A/B arm: pinned to `quiz`, and the stored record reads `quiz`;
- flags, date gates and the Chrome version: the fixed battery passes 31/31
  on the same laptop, with the same Chrome 157, against the same bundle.

**Real users are unaffected.** This is test harness state only.

**Proof:**
- The unfixed battery, run three times on the laptop (twice by the caller,
  once here at 11:59 +03), gave 21/31 each time.
- The fixed battery, run with the orphan still holding `127.0.0.1:9222`, gave
  **31/31**.

**Fix (this PR):**
- `scripts/smoke-test.js` starts Chrome with `--remote-debugging-port=0` in a
  `mkdtemp` profile. It reads the port Chrome picked from that profile's own
  `DevToolsActivePort` file (`waitForDevToolsPort` in
  `scripts/smoke/lib.mjs`), so the port can only belong to its own browser.
- On a crash, SIGINT, SIGTERM or SIGHUP it kills its Chrome and removes the
  profile, so a killed run no longer leaves an orphan.

**Tests** (`tests/smoke-workflow.test.js`), each proven by a deliberate break:
- Putting `9222` back in the spawn and in `getJSON` failed "the battery
  drives its OWN Chrome…".
- Parsing the whole file instead of its first line failed "DevToolsActivePort:
  the first line is the port…".
- Full suite: 3,083 tests passed. Lint: 0 errors, 43 warnings.

**Founder, laptop hygiene (not in git):**
- The orphan is still running. `kill 60653` frees 9222 for any other tool
  that hard-codes it.
- Two more orphans from `launchChrome` (lib.mjs, pid-derived port) have been
  up since 11-22 11:17: PIDs 41867 (:9638) and 41923 (:9694).
- 31 `/tmp/chrome-smoke-*` profile directories are left over from
  earlier runs.
