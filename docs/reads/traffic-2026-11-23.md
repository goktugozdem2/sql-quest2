# Traffic sources — C8 Monday read (2026-11-23)

Brief: `docs/agent/fleet/C8-traffic-sources.md`. Counts only, no customer data.

**Windows.** W1 = 11-16 → 11-22 and W0 = 11-09 → 11-15, both UTC full days. "Last day" = 11-22.

**Method.**
- Data: `pro_events`, events `landing_view` and `app_opened`. A person is `coalesce(aid, username)`.
- Source: the person's first `landingSrc` in the window.
- Outcomes are per person in the same window: `app_opened`, `challenge_solved`, and trial or purchase (`pro_trial_started` / `pro_purchase_completed`, `reason='stripe_webhook'`).
- The exclusions are README rule 2, plus three more:
  - stamped bots, the three viewports, `aocr.org`, and internal usernames;
  - the founder's 11-20 checkout tests (guest sessions with `email_link`);
  - Asia/Shanghai landing rows with no source before 11-22 (metrics.md);
  - **two hand rules that are new in this read**, listed under "Not people".

## Not people — two new waves, both excluded by hand here

### N1. The topic-page crawler (`topic1lang`, #246 not merged, so no stamp yet)

- **Shape:** its first `app_opened` has no `landingSrc`, an `arrivalSrc` starting `challenges-`, and `langs = 1`.
- **Size:** 53 people in the week of 11-09, 98 in the week of 11-16, and 69 more on 11-23 by 15:52 UTC.
  - On 11-22 there were 81, across 23 time zones and 81 distinct viewports.
- **Behaviour:** `challenge_opened` → `first_challenge_started`, then nothing. **None has ever run a query, solved or signed up.**
- **Effect:** without this rule, W1's "internal door" row reads 121, not 39, and the last day reads 89, not 8.
- **Next:** #246 stamps it. Until it merges, every read applies the rule by hand. It is now in the README list.

### N2. New: a UTC landing crawler with spoofed referrers (from 2026-11-22)

- **Shape:** `landing_view` rows with time zone `UTC` from people who never reach `app_opened`.
  - The user agent and the window size disagree: an iPhone user agent with `desktop:1920x1080`, an iOS 10 user agent with `desktop:1600x1200`, and a Nexus 5 user agent on desktop or mobile sizes.
  - One event per person, one page each, across most company pages and blog posts.
- **Size:**
  - Before 11-22, UTC landing people ran 3–5 a day.
  - **On 11-22 there were 77; of them, 0 opened the app.** About 26 carried `ref https://bing.com/` (so `landingSrc = search:bing`) and about 39 carried no source.
  - 11-23 to 15:52 UTC: 17, and 0 opened the app. Some of these carry `ref https://www.google.com/`.
- **Why now:** landing rows carry a window size from 11-22. The wave also starts on 11-22, at 3–5 a day before, so this is a real start, not only newly visible.
- **Effect on this read:**
  - Bing W1 is 40 people, not 66 raw. Bing's last day is 4, not 30.
  - "None: landed on a page" on 11-22 is 92, not 139.
- **Hand rule used here:** a person whose `landing_view` has `tz = 'UTC'` on or after 2026-11-22 and who has no `app_opened` in the window.
  - This drops very few real people: real UTC landers who never open the app are 3–5 a day.
  - Per the metrics.md trap, the durable fingerprint should be the user agent / window-size mismatch, not the time zone. That is B2's to stamp, in `src/utils/bot-signals.js` + `src/track.js`. BACKLOG line written.
