**Scope:** the stack #249 (`feat/debug-question-type`, ids 331–342) + #252
(`feat/debug-pro-line`), with `origin/main` merged in, on branch
`qa/debug-flag-on`. The founder's rule of 2026-11-23 applies: no separate price,
Pro opens all 12, and a free account solves Easy and Medium within the 10 free

**How:**
- Two local builds:
  - flag on, with `debugQuestions: true` set locally, never committed;
  - flag off, as committed.
- Both served from `public/` copies.
- Headless Chrome through `scripts/smoke/lib.mjs`.
- Hermetic: every Supabase, edge-function, `/api/` and analytics call is answered
  in-page, and the same hosts are blocked at the network layer as a backstop.
  - The account load (`rpc/sq_load_account`) is stubbed per persona.
  - `sq_save_user` is answered 204 and kept in the page.
- Result: **0 requests reached production**, and every `ai-tutor` call (the live
  nudge, 1 per open) was answered by the stub. Nothing was billed.

## Fixed in this PR

- **The cold-start gate's Pro path lost the `debug_lock` label.** This is the one
  wall a guest with no solves meets on a Hard Debug item.
  - `openProFromColdStart` now looks up the item the gate was opened for, as
    `openProFromPreviewCatcher` already did, and passes it through
    `withDebugLock`.
  - The modal copy still keys on `cold_start_anyway`.
  - New test in `tests/debug-pro-line.test.js`. The break that proved it: the
    unwrapped `setProModalReason({ type: 'cold_start_anyway', … })` failed it
    by name.
  - `tests/free-tier-boundary.test.js` now accepts the wrap, and still fails
    when the reason type changes (break: type set to `hard_challenge`).
